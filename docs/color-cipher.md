# Color Cipher

**Hide a pattern of colors. Crack your rival's first.** Color Cipher is RivalRush's second
game: an original two-player deduction duel with colored tiles instead of digits. It runs on the
same rooms, invites, timers, reconnect, rematch, match history and stats as Crack the Code. Only
the rules plug-in and the board are new.

|                        | Crack the Code       | Color Cipher                                  |
| ---------------------- | -------------------- | --------------------------------------------- |
| Secret                 | 3–5 different digits | 4 tiles from 6 colors, **repeats allowed**    |
| Feedback               | Bulls / cows         | **Exact** / **Close**                         |
| Combinations (default) | 5,040                | 1,296                                         |
| Feels like             | Logic with numbers   | Logic with patterns; repeats make it trickier |

## Rules

| Rule            | Behaviour                                                                                               | Value        |
| --------------- | ------------------------------------------------------------------------------------------------------- | ------------ |
| Pattern         | 4 positions, each one of 6 colors. A color may appear more than once                                    | fixed        |
| Setup           | Both players lock a pattern. When the setup timer ends, missing patterns are generated by the server    | 60 s         |
| First player    | Random for the first game; **swaps on every rematch**                                                   | —            |
| Turns           | Strictly alternating                                                                                    | —            |
| Feedback        | **Exact** = right color, right position. **Close** = right color, wrong position. The rest are misses   | —            |
| Turn timer      | When it runs out, the turn is **used up** (counts toward the limit) and passes                          | 45 s (30–90) |
| Guess limit     | Per player; counts guesses **and** timed-out turns                                                      | 10 (8–12)    |
| Duplicate guess | Repeating your own earlier guess is rejected (`DUPLICATE_GUESS`) and does not use the turn              | —            |
| Equalizer       | If the **first** player cracks the pattern, the second gets **one last guess**. Crack it too → **draw** | —            |
| Out of guesses  | Both players used all turns without cracking → **draw**                                                 | —            |
| Forfeit         | "Give up", or leaving the room mid-game = immediate loss                                                | —            |
| Disconnect      | Away longer than the grace period = loss (`abandoned`)                                                  | 60 s         |
| Rematch         | Both vote → new game session in the same room, new patterns, other player first                         | —            |

### Design decisions

- **4 positions × 6 colors with repeats** (1,296 patterns). A strong player needs about 5
  guesses; casual players need 6–9. A limit of 10 leaves room for mistakes and keeps a game
  under ~5 minutes at 45 s turns. Without repeats (360 patterns) the game is noticeably easier
  and closer to Crack the Code; repeats are what make it a different puzzle.
- **Only turn time and guess limit are configurable.** Pattern length and color count are fixed
  for the MVP (they are stored in the settings, so records stay self-describing if this changes).
- **The equalizer is kept.** It is the same fairness argument as Crack the Code: with strict
  alternation, when the first player cracks on turn k the second player has used k−1 turns, so
  one last guess gives both the same number of attempts.
- **Feedback is a count, not a position map.** Like the classic family of these games, Exact and
  Close tell you how many, never which tiles. That is what makes it a deduction game.
- **Colors carry symbols.** Each color also has its own shape, so the game is playable with
  color-vision deficiency.

| Id  | Color | Symbol |
| --- | ----- | ------ |
| 0   | Ruby  | ●      |
| 1   | Amber | ▲      |
| 2   | Sun   | ■      |
| 3   | Leaf  | ◆      |
| 4   | Sky   | ★      |
| 5   | Plum  | ✚      |

Patterns travel as strings of color ids, e.g. `"0312"` = Ruby, Leaf, Amber, Sun. Below, the
examples use letters for readability: R = Ruby, A = Amber, S = Sun, L = Leaf, K = Sky,
P = Plum.

## Scoring (duplicates)

The algorithm, applied to the secret S and the guess G (same length):

1. **Exact** = the number of positions i where S[i] = G[i].
2. **Common** = the sum over every color c of min(count of c in S, count of c in G).
3. **Close** = Common − Exact.

Each secret tile is matched at most once, and an exact match is never also counted as close. The
result does not depend on the order tiles are compared in, so it is deterministic.

| #   | Secret  | Guess   | Exact | Close | Why                                                                           |
| --- | ------- | ------- | ----- | ----- | ----------------------------------------------------------------------------- |
| 1   | R K L S | R L S K | 1     | 3     | R in place; L, S, K present elsewhere                                         |
| 2   | R R L K | R R R R | 2     | 0     | Only two Rs in the secret, both matched exactly; the other two Rs miss        |
| 3   | R R L K | L R R R | 1     | 2     | Position 2 exact. Rs: min(2, 3) = 2, one already exact → 1 close; L → 1 close |
| 4   | R L K S | R R R R | 1     | 0     | One R in the secret, matched exactly                                          |
| 5   | R R R R | R L K S | 1     | 0     | The single R in the guess is exact; nothing else is in the secret             |
| 6   | R R L L | L L R R | 0     | 4     | Every tile present, none in place                                             |
| 7   | R L R L | L R L R | 0     | 4     | Same, alternating                                                             |
| 8   | R R L K | K R R L | 1     | 3     | Position 2 exact; second R, L and K present elsewhere                         |
| 9   | S S S K | K S S S | 2     | 2     | Positions 2 and 3 exact; third S and K swapped                                |
| 10  | R L K P | A A S S | 0     | 0     | No color in common                                                            |
| 11  | R R K K | R K R K | 2     | 2     | Positions 1 and 4 exact; the other R and K swapped                            |
| 12  | R L L L | L L L R | 2     | 2     | Positions 2 and 3 exact; one L and the R swapped                              |
| 13  | R L K S | R L K S | 4     | 0     | Cracked                                                                       |
| 14  | P P A K | P K P A | 1     | 3     | Position 1 exact; the second P, A and K present elsewhere                     |
| 15  | R R R L | L L L R | 0     | 2     | Common: R min(3, 1) = 1, L min(1, 3) = 1; no position matches                 |
| 16  | S S K K | S K S K | 2     | 2     | Positions 1 and 4 exact; the remaining S and K swapped                        |

## State machine

Same phases as Crack the Code. The room around it is unchanged (LOBBY → READY → IN_GAME →
FINISHED → rematch).

```
SETUP ──both patterns locked / setup deadline (server fills missing)──▶ PLAYING
PLAYING ──first player cracks──▶ LAST_CHANCE ──second player's guess or timeout──▶ FINISHED
PLAYING ──second player cracks / both out of turns──▶ FINISHED
SETUP | PLAYING | LAST_CHANCE ──FORFEIT──▶ FINISHED     ──grace expired──▶ ABANDONED
```

| Phase       | Allowed                                   | Rejected                                                             | Timer                        | Leaves when                                                                   |
| ----------- | ----------------------------------------- | -------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------- |
| SETUP       | `SET_SECRET` (once per player), `FORFEIT` | `GUESS` → `GAME_NOT_STARTED`; second secret → `SECRET_ALREADY_SET`   | 60 s setup deadline          | Both locked → PLAYING; deadline → server generates missing patterns → PLAYING |
| PLAYING     | `GUESS` by the player on turn, `FORFEIT`  | Out of turn → `NOT_YOUR_TURN`; `SET_SECRET` → `GAME_ALREADY_STARTED` | Turn deadline (turn seconds) | Crack, both out of turns, forfeit, abandon                                    |
| LAST_CHANCE | `GUESS` by the second player, `FORFEIT`   | As PLAYING                                                           | Turn deadline                | The second player's guess or timeout                                          |
| FINISHED    | nothing                                   | Every action → `GAME_FINISHED`                                       | none                         | Room rematch starts a new session                                             |
| ABANDONED   | nothing                                   | Every action → `GAME_FINISHED`                                       | none                         | Room rematch starts a new session                                             |

Every accepted action and every applied timeout bumps the game `version` by 1. Rejected actions
change nothing. Events (public, secret-free): `secret_locked`, `playing_started`, `guess_made`
(with `guess`, `exact`, `partial`, `cracked`), `turn_timed_out`, `last_chance`, `game_over`.

### End conditions

- First player cracks on turn k → `LAST_CHANCE`; the second player always has a turn left.
  - Second player cracks → draw (`both_cracked`).
  - Second player misses or times out → first player wins (`cracked`).
- Second player cracks on turn k → second player wins at once (both had k turns).
- Second player's N-th turn ends without a crack → draw (`out_of_guesses`).
- Forfeit → `FINISHED`, reason `forfeit`. Grace expiry → `ABANDONED`, reason `abandoned`.

## Actions

Sent over Socket.IO `game:action` with `roomId`, `actionId` and `clientVersion`, exactly like
Crack the Code. Identity comes from the session token; the payload never carries a player id,
a score, feedback, a winner or a timer.

| Action       | Payload                                       | Version-independent | Validation                                                                                                    |
| ------------ | --------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SET_SECRET` | `{ "type": "SET_SECRET", "pattern": "0312" }` | yes                 | SETUP only, before the deadline, once; exactly 4 ids, each 0–5 (`INVALID_SECRET`)                             |
| `GUESS`      | `{ "type": "GUESS", "pattern": "0312" }`      | no                  | Your turn, before the deadline, turns left, valid pattern (`INVALID_GUESS`), not repeated (`DUPLICATE_GUESS`) |
| `FORFEIT`    | `{ "type": "FORFEIT" }`                       | yes                 | Any live phase                                                                                                |

Errors reuse the existing codes. `details.rule` says what was wrong: `length` (not 4 tiles) or
`color` (an id outside 0–5). Duplicate `actionId` = applied once; a `GUESS` with an old
`clientVersion` = `STALE_GAME_VERSION` with the current snapshot attached.

## Timers and reconnect

All inherited from the platform: deadlines are server timestamps; a deadline that is due is
applied before any action, so a guess arriving exactly at the deadline loses to the timeout; a
player who drops gets 60 s to come back (the turn timer keeps running meanwhile); reconnecting
returns an authoritative snapshot.

## What each player sees

`getPlayerView` returns: phase, version, settings, your own pattern (and whether the server
picked it), each player's public status (pattern locked, turns used, guesses left, cracked),
whose turn it is, the deadlines, every guess with its Exact/Close counts, and the result. The
opponent's pattern appears **only once the game is over**. `getPublicView` contains no pattern at
all. Patterns are never written to the database: match history stores guesses and counts only.

## Rematch and stats

The platform's rematch: both players vote, a new session starts in the same room with new
patterns and the other player first. Finished games are recorded once with
`gameType: "color-cipher"`. Wins, losses, draws and streaks are shared across both games (one
record per player).
