# WebSocket protocol (Socket.IO)

Connect with `io(API_URL, { auth: { token } })`. The handshake is rejected (`UNAUTHORIZED`)
without a valid session token. Each socket joins a private `user:<id>` channel; the socket id
is never used as identity.

Every client event is sent with an acknowledgement callback and gets
`{ ok: true, data }` or `{ ok: false, error, snapshot? }`. Failed `game:action`s include the
caller's authoritative `snapshot` so the client can resync immediately.

## Client → server

| Event            | Payload                                     | Ack data                                             | Notes                                                                                  |
| ---------------- | ------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `room:subscribe` | `{roomId}`                                  | `RoomSnapshot`                                       | Members only. Marks the player online (presence)                                       |
| `room:ready`     | `{roomId, ready, actionId}`                 | `RoomSnapshot`                                       | Lobby only; the host is always ready                                                   |
| `room:start`     | `{roomId, actionId}`                        | `RoomSnapshot`                                       | Host only, room READY                                                                  |
| `room:leave`     | `{roomId, actionId}`                        | `{left:true}`                                        | Mid-game = forfeit                                                                     |
| `room:rematch`   | `{roomId, actionId}`                        | `RoomSnapshot`                                       | FINISHED rooms; both votes start a new session                                         |
| `game:action`    | `{roomId, actionId, clientVersion, action}` | `RoomSnapshot`                                       | `action` is `{type:'SET_SECRET', code}`, `{type:'GUESS', guess}` or `{type:'FORFEIT'}` |
| `game:resync`    | `{roomId, knownVersion?}`                   | `{changed:false, version}` or `{changed:true, room}` | Also (re)subscribes the socket                                                         |

`actionId`: 8–64 chars `[A-Za-z0-9_-]`, unique per state-changing action. A repeated
`actionId` from the same user is not applied again; it returns the current snapshot.

`clientVersion`: the `game.version` the client last saw. `GUESS` requires an exact match.
`SET_SECRET` and `FORFEIT` are version-independent.

Throttle: 5 events/second per connection, burst 12 → `RATE_LIMITED`.

## Server → client

| Event           | Payload                                             | When                                                                                                                                                                                                                                                                |
| --------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `room:snapshot` | `RoomSnapshot` built **for that recipient**         | After every accepted change                                                                                                                                                                                                                                         |
| `room:event`    | `{type, roomId, version, at, actorId, data?}`       | Feedback: `player_joined`, `player_left`, `player_ready`, `player_online`, `player_offline`, `host_changed`, `game_started`, `secret_locked`, `playing_started`, `guess_made`, `turn_timed_out`, `last_chance`, `game_over`, `rematch_requested`, `rematch_started` |
| `room:closed`   | `{roomId, reason: 'left' \| 'expired' \| 'closed'}` | You left, or the room expired/closed                                                                                                                                                                                                                                |

## Snapshot (abridged)

```ts
RoomSnapshot {
  roomId, inviteToken, gameType, settings, status, hostId, maxPlayers,
  players: [{ userId, displayName, photoUrl, isHost, ready, online, wantsRematch, graceDeadlineAt }],
  version, createdAt, expiresAt, serverTime, gamesPlayed,
  game: { sessionId, gameType, version, result, view: CtcPlayerView } | null
}
CtcPlayerView {
  phase, version, settings, me, mySecret, mySecretAutoGenerated,
  opponentSecret /* null until FINISHED/ABANDONED */,
  players: [{ userId, hasSecret, turnsUsed, guessesLeft, cracked }],
  firstPlayerId, currentTurn, setupDeadlineAt, turnStartedAt, turnDeadlineAt,
  moves: [{ playerId, guess, bulls, cows, timedOut, at, turnNumber }], result
}
```

Countdowns: `remaining = deadline − (Date.now() + (serverTime − receivedAt))`. The client
never decides that time is up.

## Reconnect

1. socket.io-client reconnects automatically. When Telegram returns to the foreground
   (`activated`, or `visibilitychange`), the app reconnects or resyncs.
2. On `connect` the client sends `game:resync {roomId, knownVersion}` and applies the
   snapshot if it changed.
3. A cold start calls `GET /api/me/active-room` and routes back into a live game.
4. While a player has no connection during a live game, `graceDeadlineAt` is set (60 s). If
   it passes, the server applies `$ABANDON`.
